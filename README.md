# line-recruitment-system20261006

## 概要

- LINE Messaging API を利用した採用応募受付システムのV2移行版です。
- `userState:${userId}`（Script Properties）は「応募途中セッション専用」の一時データです。応募完了後の履歴情報としては使用しません。
- 完了済み応募の履歴は、Script Propertiesではなく「応募管理」スプレッドシートをSource of Truth（正）として管理します。
- LINEのWebhook再送（同一イベントの再送信）等による同一応募の二重保存を防ぐため、応募保存処理は排他ロック内で「userStateがまだ残っているか」を確認してから行う、最小限の冪等性対策を備えています。

## セットアップ手順

- 応募No採番・応募管理シート保存の排他制御には `LockService.getScriptLock()` を使用しています。GAS標準機能のため、追加の設定・有効化作業は不要です。

## 環境変数 / スクリプトプロパティ

- `userState:${userId}`：応募途中ユーザーの一時的なセッションデータです。応募管理シートへの保存成功後、自動的に削除されます。応募完了済みかどうかの判定には使用しません。
- その他のスクリプトプロパティについては別途の調査資料を参照してください。
- 秘密情報（LINEチャネルアクセストークン等）はScript Propertiesではなく、本番と同様にスプレッドシートの「設定」シートで管理します。実値はこのREADMEには記載しません。

## デプロイ手順

- 今回の変更によるデプロイ手順の変更はありません。

## 運用手順

- 応募完了後は「応募管理」シートに応募履歴が残ります。担当者は応募履歴の確認にはこのシートを使用してください。
- 過去に応募完了したユーザーが「応募開始ワード」を送信した場合、または再度友だち追加（followイベント）した場合のいずれであっても、新しい応募フローは開始されません（応募管理シートの履歴をもとに判定します）。通常の新規ユーザーのfollowイベントは、従来通り応募フローが自動開始されます。

## トラブルシューティング

- LINEへの完了reply（返信）が失敗した場合でも、応募データの保存自体は成功している可能性があります。ユーザーから「返信が来ない」等の問い合わせがあった場合は、まず「応募管理」シートに該当ユーザーの応募が保存されているか、および処理ログ・エラーログを確認してください。
- 処理ログに `APPLICATION_DUPLICATE_SAVE_SKIPPED` が記録されている場合は、Webhookの再送等により同一応募の保存処理が複数回実行され、2回目以降が重複保存として正しくスキップされたことを示します。異常ではありませんが、頻発する場合はLINE側の配信状況（応答遅延など）を確認してください。
